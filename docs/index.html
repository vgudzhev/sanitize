Your secrets never leave
your machine.

pi-scrub is a local scrubbing layer for coding agents. It intercepts every request to cloud LLMs and replaces secrets and PII with stable placeholders — so the model can still reason about your code, but your credentials never hit the wire.

Architecture

Scrub at ingress, verify at egress

Two components work together: a stateless Python detection service and a TypeScript extension that hooks every stage of your coding agent's lifecycle. The session stays scrubbed at rest — rehydration happens only at tool boundaries and display. 

 you type / paste ──► [input hook] ──► scrub ──► session (clean) ─┐
                                                                  │
 tool runs ──► real output ──► [tool_result hook] ──► scrub ────────┤
                                                                  ▼
                                                       [context hook]  (defense in depth)
                                                                  ▼
                                                [before_provider_request]  (egress verify)
                                                                  ▼
                                                           cloud model
                                                                  ▼
                                                   response with [[placeholders]]
                                                                  │
     ┌────────────────────────────────────────────────────────────┤
     ▼                                                            ▼
 [tool_call hook]: rehydrate args               [display]: rehydrate for you
   tool executes with real values                  you read real values

Fail closed

If the scrubber is unreachable, nothing is sent. Content is replaced with [[SCRUBBER_UNAVAILABLE]].

Stateless service

The detection service never stores content or sees the vault. It receives text, returns spans, and forgets.

Stable placeholders

Same value → same placeholder across the whole session. The model can track relationships in your data.

Provider-agnostic

Works with any cloud model: Anthropic, OpenAI, Google, Mistral, Ollama, or custom providers.

Detection

Six layers of defense

Detection layers run in order, results are merged. Overlapping spans are resolved by highest score, then widest span. Each layer adds to what the previous layers found — no layer can suppress findings from another.

Layer 1

Secret patterns

AWS/GCP/Azure keys, GitHub/GitLab tokens, Slack, Stripe, JWTs, private key blocks, password assignments, DB connection URLs with credentials.

gitleaks TOML rules → Presidio PatternRecognizers
Layer 2

Entropy analysis

Shannon entropy over tokens ≥ 20 chars in credential contexts (=, :, Bearer, Authorization). Catches unprefixed random secrets.

Custom EntropyRecognizer
Layer 3

Structured PII

Email addresses, phone numbers, IBANs, credit card numbers (Luhn), IPv4/IPv6, URLs, MAC addresses, dates of birth.

Presidio built-in recognizers
Layer 4

Contextual PII

Person names, physical addresses, organization names, internal hostnames, project codenames. Labels are configurable per project.

GLiNER NER model
Layer 5

Custom vocabulary

Your own regexes and literal strings — customer ID formats, internal domains, employee IDs, anything org-specific.

sanitize.yaml config
Layer 6

Local LLM recognizer

An optional small local model that catches secrets no pattern matched. Additive-only: it can never remove findings from layers 1–5.

Ollama / llama.cpp · optional
Why

What pi-scrub protects you from

Every intermediary between your machine and the model — routers, proxies, provider logging, breaches — could extract credentials and PII from your prompts and tool results.

🛡

Debugging with real configs

Paste production configs, log files, and .env files into your agent. DB URLs, API keys, and passwords are scrubbed before they leave your machine — the model still sees the structure it needs to debug.

🔍

Code review with context

Let the agent read your actual infrastructure files. Private keys, cloud credentials, and internal hostnames are replaced with consistent placeholders so the model reasons about the real architecture.

👥

Customer data in logs

When the agent reads application logs, emails, phone numbers, and names are caught by the PII layers. The model sees [[EMAIL_1]] and [[PERSON_1]] — enough to trace the issue.

📤

Safe session sharing

Because the session stays scrubbed at rest, exports and shared sessions contain only placeholders. You can share a debugging session with a colleague without leaking secrets.

🏢

Org-wide policy

Deploy sanitize as a shared service with a signed central policy. Local configs can only tighten the policy, never loosen it. Audit events report category counts, never content.

🔗

Any LLM client via gateway

Gateway mode is a local HTTP proxy for any OpenAI/Anthropic SDK client. Point your base_url at it and get the same scrubbing protection without changing a line of application code.

Gateway mode

Any LLM client, zero code changes

Gateway mode is a local HTTP proxy that sits between any OpenAI/Anthropic SDK and the real API. Point your base_url at it and get scrubbing protection for any client.

How it works

The gateway walks every request body recursively — messages, system prompts, tool descriptions, function arguments — scrubs all secrets, then forwards the clean request to the real provider. Responses are rehydrated on the way back, including streaming with placeholder-aware chunk buffering.

Session management

Each session gets its own vault. Send an X-Sanitize-Session header to reuse a vault across requests. Sessions expire after 1 hour of inactivity.

Streaming support

Fully supported. The gateway buffers text deltas to handle placeholders that span SSE chunk boundaries, then rehydrates each chunk before forwarding.

OpenAI Python SDK
from openai import OpenAI client = OpenAI( base_url="http://localhost:7412/openai/v1", api_key="sk-your-real-key", ) resp = client.chat.completions.create( model="gpt-4", messages=[{ "role": "user", "content": "My key is AKIAIOSFODNN7..." }], ) # OpenAI sees: "My key is [[AWS_ACCESS_KEY_1]]" # You see: the real response, rehydrated
Anthropic Python SDK
from anthropic import Anthropic client = Anthropic( base_url="http://localhost:7412/anthropic", api_key="sk-ant-your-key", ) resp = client.messages.create( model="claude-sonnet-5", max_tokens=1024, messages=[{ "role": "user", "content": "DB: postgres://admin:s3cret@..." }], )
Detection API

Use the detection service directly

The detection service exposes a simple HTTP API. Send text, get back spans with type, position, confidence score, and which detector found it.

Request
curl -X POST http://localhost:7411/v1/detect \ -H "Content-Type: application/json" \ -d '{ "text": "email me at alice@corp.com, key AKIAIOSFODNN7EXAMPLE", "hints": {"source": "tool_result", "tool": "bash"}, "policy": "default" }'
Response
{ "spans": [ { "start": 12, "end": 26, "type": "EMAIL_ADDRESS", "score": 0.85, "detector": "presidio" }, { "start": 32, "end": 52, "type": "AWS_ACCESS_KEY", "score": 0.99, "detector": "regex:gitleaks" } ], "stats": { "ms": 42, "detectors_run": [...] }, "policy_version": "2026-09-16.1" }
Quick start

Up and running in 5 minutes

Everything runs locally. The detection service is Python, the extension is TypeScript.

1

Clone and install the detection service

git clone https://github.com/vgudzhev/sanitize.git cd sanitize/sanitize python3.12 -m venv .venv && source .venv/bin/activate pip install -e ".[dev]" python -m spacy download en_core_web_sm
2

Start the service

uvicorn sanitize.app:app --port 7411 # Verify: curl http://localhost:7411/v1/health
3

Install the extension

cd ../extension && npm install mkdir -p ~/.pi/agent/extensions/pi-scrub ln -s "$(pwd)/src/index.ts" ~/.pi/agent/extensions/pi-scrub/
4

Use pi as usual

Everything is automatic. Paste something with a secret and see it scrubbed.

# You type: My AWS key is AKIAIOSFODNN7EXAMPLE and password is hunter2 # The model receives: My AWS key is [[AWS_ACCESS_KEY_1]] and password is [[GENERIC_SECRET_1]]
Configuration

Customize to your stack

Policy is merged from built-in defaults, user-level config, and per-project overrides. Project configs can only add detections, never disable built-in secret patterns.

✓

Custom patterns — match your own secret formats like employee IDs or customer tokens

✓

Literal deny lists — always catch specific internal domains or project names

✓

GLiNER label tuning — add domain-specific NER labels like "medical condition" or "project codename"

✓

Allow lists — suppress false positives on known-safe values like 127.0.0.1

✓

Path deny list — block ~/.ssh/*, .env*, *.pem from ever entering context

✓

Vault persistence — AES-256-GCM encrypted, survives session restarts

~/.pi/agent/sanitize.yaml
# Custom detection patterns custom: patterns: - name: EMPLOYEE_ID regex: "EMP-[0-9]{6}" - name: CUSTOMER_ID regex: "CUST-[0-9]{8}" literals: - "acme-internal.corp" - "project-manhattan" # GLiNER NER labels detectors: gliner: labels: - person - address - organization - internal hostname - project codename threshold: 0.5 # Never scan these files deny_paths: - "~/.ssh/**" - "**/.env*" - "**/*.pem" - "**/*.key" # Known-safe values allow: - "127.0.0.1" - "example.com" - "test@example.com"
